# kelip-paper-reading-plus · v0.2.0

[English](README.en.md) · [版本记录](CHANGELOG.md)

用原图、公式、数据样本和代码读懂论文，同时核验关键实验、局限与项目应用条件。

本仓库是 [skJack/kelip-paper-reading](https://github.com/skJack/kelip-paper-reading) 的增强衍生版本，基于上传快照 `925953b15813f18b25eeb1a1dca9790f54a47498`。保留原作者 MIT 许可证；不代表原作者发布或背书。

## 本版本具体优化了什么

原版已经提供了六站带读、原图展示、数字算例、论文与代码对照，以及随读随记的笔记机制。本版本保留这些基础，重点增强**证据判断、按需阅读、项目应用和材料可靠性**。下表比较对象是上述原版快照，不代表上游后续版本的状态。

### 阅读与分析能力

| 方面 | 原版的默认设计 | v0.2.0 的具体改进 | 对使用者的价值 |
|---|---|---|---|
| 阅读入口 | 以逐站精读为主，每站结束询问是否继续 | 增加快速判断、逐步精读、项目应用三种模式；按用户目的选择，支持一次讲完 | 简单问题可直接回答，深入学习仍能逐步展开 |
| 实验与局限 | “实验和地位”是六站之后的可选环节 | 每种模式都覆盖核心结果和至少一项证据限制；精读中设为必讲环节 | 除了理解方法，还能判断实验支持结论到什么程度 |
| 公平比较 | 要求介绍结果、对比对象和局限，但缺少统一检查表 | 检查数据量、预训练、参数量、训练/推理预算、消融、重复实验和外部验证 | 避免把更多数据或更长训练带来的提升直接归因于新方法 |
| 结论可追溯 | 已要求区分论文、代码和推测，并为数字注明出处 | 增加证据表，记录来源版本、PDF 位置、代码提交号、限定条件及支持程度；区分作者报告与独立实测 | 便于复查，也能看清哪些结论尚未确认 |
| 数字与教学示例 | 强调用真实数字或玩具算例解释机制 | 要求真实样本有来源，示意数字明确标注，简化例子说明省略条件；修正“均值接近零即可判断增量动作”的不充分推断 | 保留易懂的讲法，减少把示例或线索当成证明 |
| 领域适配 | 流程和样例主要围绕机器人、VLA、世界模型 | 增加语音、视频、医学/病理 AI 检查表；理论和综述论文可按论证结构展开 | 阅读不同领域时关注相应指标、数据划分和验证条件 |
| 项目应用 | 资源需求和应用问题分散在讲解中 | 增加适配表和最小验证模板：输入输出、数据差距、目标硬件、延迟、许可、通过阈值与停止条件 | 能进一步回答“是否值得投入验证、先验证什么” |
| 展示与进度 | 统一使用 Unicode 公式、字符流程图；笔记中记录问答 | 根据宿主能力选择公式/图表展示；增加带材料身份的阅读进度模板；个人偏好放到私有位置 | 改善阅读、续读和共享使用时的体验 |

这些是对 agent 行为的流程约束与模板增强；实际讲解质量仍取决于执行模型、可用材料和核验过程。优化作用于阅读流程和材料管理，论文模型的实际效果仍需独立验证。

### 脚本可靠性与具体修复

| 问题或场景 | v0.2.0 的处理 | 对应实现 |
|---|---|---|
| 解压目录边界使用字符串前缀判断，LaTeX 引用可能超出源码目录 | 使用解析后的路径包含关系校验，拒绝越界与特殊归档条目；限制下载、解压大小及文件数量 | `common.py`、`fetch_paper.py` |
| 重跑时元数据更新，PDF/源码仍可能是旧版 | 固定论文版本，记录 PDF/源码哈希；材料不一致时停止，新版本使用新目录 | `fetch_paper.py` |
| API 失败后覆盖原有作者、摘要等信息 | 保留已有有效元数据，仅以成功取得的有效字段更新 | `fetch_paper.py` |
| 链接得分高就被视为官方仓库 | 自动发现结果只列为候选；核对后通过 `--code` 选择，记录来源与提交号 | `fetch_paper.py` |
| 任意非空代码目录被认为已经克隆成功 | 核对有效 Git 仓库、远程地址和提交号；离线未下载状态明确记录为 `not-cloned` | `fetch_paper.py` |
| 人工重裁的图片被再次运行覆盖 | 按人工标记和图片哈希保护；没有旧哈希时保守保留，用户目录不被自动接管 | `extract_figures.py`、`crop.py` |
| 直接运行裁图脚本绕过材料版本检查 | 独立提图和针对 `paper.pdf` 的裁剪也检查已记录的 PDF 哈希 | `extract_figures.py`、`crop.py` |
| 输出文件是符号链接时，可能覆盖目录外的文件 | 衍生文本、索引和自动生成 PNG 使用原子替换；裁剪输出拒绝符号链接与覆盖输入 | `common.py` 及三个处理脚本 |
| 无效 PDF 先落盘，导致后续重试被已有坏文件阻挡 | 在保存新 PDF 前验证可打开、非空且未加密；导入失败后可重新提交有效文件 | `fetch_paper.py` |
| 首次阅读就准备全部材料；缺少明确离线入口 | 增加 `--level quick` 和 `--offline`；按需补充源码、图表与代码 | `fetch_paper.py` |
| 页码、网格步长或输出路径不合适 | 校验页码、裁剪范围、DPI 和步长，自动创建输出父目录 | `crop.py` |

脚本自动记录材料身份并保护文件；“是否官方”“实验是否充分”“能否用于项目”等判断仍由 agent/使用者核验，不由下载脚本自动认证。

### 一个使用场景

如果你问“这篇视频模型能否替换现有系统”，项目应用模式会：

1. 解释论文任务、输入输出和关键结果，注明数字来自哪里。
2. 核对基线是否公平、是否测试过新场景、是否提供目标硬件上的延迟。
3. 把“原文已支持”“需要推断”“没有提供”的信息分开。
4. 根据现有系统的要求列出差距，并提出样本、指标、通过门槛和停止条件。

例如，论文只有 GPU 测速时，CPU 延迟会记录为“待实测”；论文未做外部场景验证时，也不会直接得出“可以替换”的结论。

### 验证到了什么程度

- **脚本回归：**37 项离线测试，覆盖版本、缓存、路径、文件保护、裁图、离线和失败恢复等场景。
- **兼容性：**v0.2.0 在 GitHub Actions 的 Python 3.10、3.12、3.13 三组测试均通过。[查看该版本测试记录](https://github.com/blueapple2000/kelip-paper-reading/actions/runs/40873936654)。
- **独立检查：**额外复核异常导入、输出符号链接和直接提图等边界情况，并做了一次合成论文的带读演练。
- **仍待验证：**真实论文在线下载的长期稳定性、各类期刊版式的裁图准确率、大规模讲解质量及实际部署效果。没有将这些结果包装成已完成的测评。

## 三种阅读方式

| 模式 | 示例 | 内容 |
|---|---|---|
| 快速判断 | “这篇值得继续研究吗？” | 任务、贡献、证据、局限，一次回答 |
| 逐步精读 | “带我读懂这篇论文” | 动机→架构→训练→数据→信息流→例子→实验与局限 |
| 项目应用 | “能替换现有系统吗？” | 适配差距、资源证据、最小验证计划 |

尊重“直接讲某一部分”“一次讲完”等要求；不强制每站等待确认。关键数字需要原文位置和版本；推断、独立实测、作者报告及教学示例分开标注。

## 安装与使用

需要 **Python 3.10+**、PyMuPDF；可选 Git 用于读取代码。本仓库已公开，可直接浏览、下载或克隆。

```bash
git clone https://github.com/blueapple2000/kelip-paper-reading.git
cd kelip-paper-reading
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell 改用：.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

在支持本地 skills 的 agent 中，按该宿主规则安装此目录；或让 agent 读取本仓库的 `SKILL.md`。本仓库不自动修改任何 agent 配置。可用提示：

> 使用 kelip-paper-reading，快速判断这篇论文的核心贡献、实验是否支持其结论，以及适合什么应用。

## 材料获取

```bash
# 第一轮只获取 PDF、文本和大纲
python scripts/fetch_paper.py 2410.24164v1 --dest ./papers/example-v1 --level quick

# 继续补充源码、图表和候选代码链接
python scripts/fetch_paper.py ./papers/example-v1 --level full

# 离线分析本地 PDF
python scripts/fetch_paper.py ./input.pdf --dest ./papers/local --offline

# 人工核对仓库归属后再指定代码；URL 必须为 GitHub HTTPS 仓库根地址
python scripts/fetch_paper.py ./papers/example-v1 --code https://github.com/owner/repo

# 仅记录选择，不下载代码
python scripts/fetch_paper.py ./papers/example-v1 --code https://github.com/owner/repo --no-clone
```

一个目录固定一篇论文的一个版本。重复运行时直接传论文目录；获取新版本使用新目录。脚本不自动更新已有代码，以保持引用提交一致。

`--level quick` 避免预先下载源码、裁全部图片和查找代码。`--offline` 禁止网络与克隆，但仍处理本地已有材料。联网请求有超时和大小限制，实际耗时取决于网络及论文大小，不承诺固定秒数。

## 可追溯性与文件保护

- `meta.json`：PDF 哈希、arXiv 固定版本、源码各文件哈希、来源状态、候选代码及所选仓库提交号。
- 论文版本无法确认时明确标记。旧目录的源码无法证明与 PDF 一致时标为 `user-or-legacy-source-unverified`，关键公式和表格需要人工对照 PDF。
- 自动发现的链接只进入 `code_candidates`；分数不代表官方身份。`--code` 表示用户/agent 已核对后作出的选择，脚本不作独立认证。
- 修改或替换固定版本的 PDF/源码时停止处理，避免旧笔记混入新材料；独立裁图入口也检查 PDF 哈希。
- 非空代码目录必须是来源匹配的有效 Git 仓库；不会清空用户目录。
- 人工修改过的图片按标记或内容哈希保护。旧版索引没有哈希时保守保留；需要重新生成时，在备份后明确移走对应图片。
- 用户自己的 `figures/` 不被覆盖；已有 `figures-auto/` 也有用户内容时自动选择其他目录。
- 源码归档、LaTeX 引用限制在源码目录内；限制下载与解压体积。只读论文代码，不执行其脚本。

## 裁图与输出

```bash
python scripts/extract_figures.py ./papers/example-v1
python scripts/crop.py ./papers/example-v1/paper.pdf --page 3 --grid
python scripts/crop.py ./papers/example-v1/paper.pdf --page 3 0.1 0.1 0.9 0.6 -o ./papers/example-v1/figures/fig-01.png
```

图表索引中保留页码、caption、裁剪坐标及人工修正信息。重跑不会覆盖人工修图。先查看 `_contact.png`，再逐张核对关键图；坐标取值为 0–1。

逐步精读时，由 agent 按模板更新 `精读笔记.md` 和 `reading-state.json`；脚本本身只准备材料，不调用大模型或生成论文结论。个人偏好存到宿主记忆或用户指定的私有位置，不自动写入共享 skill。

## 验证与限制

```bash
python -m unittest discover -s tests -v
```

测试使用合成 PDF、临时归档、临时代码仓库与网络模拟，覆盖路径边界、版本固定、缓存保留、候选仓库处理、离线流程、人工裁图和错误参数。v0.2.0 的 37 项测试已在 Python 3.10、3.12、3.13 的 GitHub Actions 中全部通过；本地验证环境为 Python 3.12 / PyMuPDF 1.26.6。测试记录见上方链接，后续提交以 Actions 页面为准。

- 裁图仍依赖 caption 和版式规则，需要视觉核对；没有覆盖所有真实期刊版式。
- 扫描 PDF 会提示需要 OCR/视觉阅读，不内置 OCR。
- LaTeX 拍平是有限解析，不完整模拟 TeX 宏和条件编译。
- 无代码/权重时仍可解释论文，但不能声称已复现或已验证部署性能。
- 此版本不声称真实论文在线下载链路已全面验证；网络服务变化可能需要维护。
